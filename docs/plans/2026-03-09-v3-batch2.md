### Task 1: F-06 Flexible Duration (Priority 6, M)

> ⚠️ **Architecture impact:** DURATION changes from constant to variable. After this task, regression-verify F-03 (progress bar) and F-05 (tab title) use dynamic duration.

**Files:**
- Modify: `index.html`
- Modify: `PomodoroTimer/PomodoroTimer/TimerManager.swift`
- Modify: `PomodoroTimer/PomodoroTimer/ContentView.swift`

**Step 1: Web — Change DURATION from const to let**

```javascript
// Before:
const DURATION = 25 * 60;
// After:
let DURATION = loadDuration();

function loadDuration() {
  const saved = localStorage.getItem('pomodoroDuration');
  return saved ? parseInt(saved, 10) : 25 * 60;
}
function saveDuration(seconds) {
  localStorage.setItem('pomodoroDuration', seconds);
}
```

**Step 2: Web — Add long-press gesture detection**

On `timerDisplay`, register `mousedown`/`touchstart` → start 500ms timer. On `mouseup`/`touchend`/`mouseleave` → cancel timer. If 500ms completes and `state === 'idle'` → enter edit mode.

Handle both mouse and touch events. Prevent default on touch to avoid text selection.

**Step 3: Web — Add edit mode UI**

Define preset options: `[15, 20, 25, 30, 45, 60]` (minutes).

Edit mode:
- Hide `#actionBtn`
- Show preset container below timer display
- Each option is a clickable element showing minutes number
- Current selection has class `selected` (bold + underline)

CSS:
- `.duration-options`: flex, gap 16px, justify-content center
- `.duration-option`: font-size 16px, color `#666666`, cursor pointer
- `.duration-option.selected`: color `#000000`, font-weight bold, text-decoration underline

**Step 4: Web — Handle option selection**

Click on option → update `DURATION = minutes * 60` → `saveDuration(DURATION)` → update `remaining = DURATION` → `updateDisplay()` → exit edit mode (hide options, show button).

Click outside options → exit edit mode without saving.

**Step 5: macOS — Change defaultDuration to @Published var**

In `TimerManager`:
```swift
// Before:
static let defaultDuration: TimeInterval = 25 * 60
// After:
@Published var selectedDuration: TimeInterval

init() {
  self.selectedDuration = UserDefaults.standard.double(forKey: "pomodoroDuration")
  if self.selectedDuration == 0 { self.selectedDuration = 25 * 60 }
  self.remaining = self.selectedDuration
  // ... rest of init
}
```

Update all references to `defaultDuration` → `selectedDuration` throughout `TimerManager` (start, reset, progress calculations).

**Step 6: macOS — Add long-press + picker in ContentView**

On `Text(timeString)`, add `.onLongPressGesture(minimumDuration: 0.5)` → toggle `@State var isEditingDuration = true`.

When `isEditingDuration && timerManager.state == .idle`:
- Show overlay with preset buttons (15/20/25/30/45/60)
- Selection → update `timerManager.selectedDuration` + save to UserDefaults + dismiss overlay
- Tap outside → dismiss without saving

**Step 7: Regression verification**

After completing F-06:
- [ ] F-03 progress bar uses dynamic duration (not hardcoded 25*60)
- [ ] F-05 tab title shows correct time for non-25min durations
- [ ] F-08 counter still increments regardless of duration
- [ ] `dismissAlert()` resets to current duration, not hardcoded

**Verify:**
- Idle → long press → options appear, button hidden
- Select 15 min → display shows 15:00, persists after refresh
- Start 15 min timer → progress bar fills correctly
- Tab title shows correct countdown for 15 min session

### Task 2: F-02 Richer Audio (Priority 7, M)

> Independent of F-06. No architecture impact.

**Files:**
- Modify: `index.html`
- Modify: `PomodoroTimer/PomodoroTimer/AudioManager.swift`

**Step 1: Web — Rewrite playAlertSound()**

Replace current `playAlertSound()` with harmonic-rich version:

Each of 4 notes:
- Create 3 OscillatorNodes: fundamental `f`, 2nd harmonic `2f`, 3rd harmonic `3f`
- Gain ratios: 1.0 : 0.3 : 0.1
- Volume sequence: `[0.15, 0.2, 0.3, 0.35]`
- Note spacing: 600ms
- ADSR per note:
  - Attack: `linearRampToValueAtTime(peakGain, startTime + 0.01)` (10ms)
  - Release: `exponentialRampToValueAtTime(0.001, startTime + 0.5)` (from ~80ms before end)

Keep existing frequency values (C5=523.25, E5=659.25) or adjust based on listening test.

**Step 2: macOS — Rewrite generateChimeBuffer()**

In `AudioManager.generateChimeBuffer(format:)`:
- For each sample in each note, sum: `sin(2π * f * t) + 0.3 * sin(2π * 2f * t) + 0.1 * sin(2π * 3f * t)`
- Apply ADSR envelope: 10ms linear attack, 80ms exponential release
- Volume sequence: `[0.15, 0.2, 0.3, 0.35]` applied as multiplier to envelope

**Step 3: Cross-platform audio tuning**

> ⚠️ Web Audio API and AVAudioEngine render audio differently. Same parameters may sound different.

- Test on Chrome + Safari (Web)
- Test on macOS with speakers + headphones
- Adjust harmonic ratios or frequencies independently per platform if needed
- Record before/after for comparison

**Verify:**
- Sound is warmer than v2 (not pure sine)
- No click/pop artifacts at note start/end
- 4-note sequence has clear soft→loud progression
- Web and macOS sound similar (not identical required)
- Volume is comfortable, not jarring

**Step 1: Technical Spike — Evaluate API paths (1-2 hours)**

Test each path in a scratch project or playground:

| Priority | Path | Test approach |

Document findings: which path works, what permissions needed, user setup steps if any.

**Step 2: Implement FocusManager.swift**

Based on spike results, implement:

```swift
class FocusManager {
  static let shared = FocusManager()
  private var wasAlreadyEnabled = false

  func enableFocus() {
    // Check if focus is already on → set wasAlreadyEnabled = true, skip
    // Otherwise → enable via chosen API path
  }

  func restoreFocus() {
    // If wasAlreadyEnabled → do nothing (user had it on)
    // Otherwise → disable focus mode
  }
}
```

Key behaviors:
- Save pre-existing state before enabling
- Restore to saved state, not "always disable"
- Silent failure: if API fails, log warning but don't throw

**Step 3: Integrate with TimerManager**

In `TimerManager`:
- `start()` → `FocusManager.shared.enableFocus()`
- `reset()` (called on dismiss and manual reset) → `FocusManager.shared.restoreFocus()`

**Step 4: Fallback — User guide document**

- Include screenshots if possible

**Verify:**
